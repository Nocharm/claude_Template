당신은 `/agile` 슬래시 커맨드를 수행 중입니다. 지금부터 이 세션의 작업은 **애자일 모드**로 진행합니다: 간단한 기능 추가·UI 개선을 최소 오버헤드로 빠르게 구현하고, 무거운 검증·문서 절차는 건너뜁니다.

이 모드가 존재하는 이유: 기본 룰(`rules/guidelines.md` §4, `rules/common/testing.md`)은 정확성이 중요한 작업에 맞춰져 있어, 버튼 스타일 수정이나 라벨 변경 같은 작은 작업에도 테스트 작성·검증 루프를 요구한다. 작은 작업에서 그 비용은 얻는 것보다 크다. 애자일 모드는 그 비용을 명시적으로 끄는 스위치다.

## 적용 판정

먼저 이번 작업이 애자일 범위인지 1초만 판단한다:

| 애자일 적합 | 부적합 (일반 모드 유지) |
|---|---|
| UI 스타일·레이아웃·문구 수정 | 데이터 모델·API 스키마 변경 |
| 단일 화면/컴포넌트의 작은 기능 | 인증·권한·결제 등 보안 표면 |
| 명백한 소규모 버그 수정 | DB 마이그레이션, 외부 연동 |
| 프로토타입·실험 코드 | 여러 모듈을 관통하는 리팩터링 |

부적합이면 한 줄로 알리고 일반 모드로 진행한다: "이 작업은 애자일 범위를 벗어나 일반 모드로 진행합니다 — <이유>."

## 완화되는 룰

| 룰 | 일반 모드 | 애자일 모드 |
|---|---|---|
| 테스트 (`testing.md`) | 새 기능마다 테스트 작성 | 새 테스트 생략. 관련 기존 테스트가 있으면 그것만 돌려 깨지지 않는지 확인 |
| 검증 루프 (guidelines §4) | 테스트 작성 → 통과 루프 | 1회 실행·스모크 확인으로 대체. 무엇을 어떻게 확인했는지 한 줄 보고 |
| 시작 체크리스트 (guidelines §1) | 목표 재진술·unknown 나열 | 생략. 모호하면 가정 한 줄 명시하고 바로 진행 |
| 계획 서술 | 다단계 plan 제시 | 생략. 바로 구현 |
| PROGRESS.md (`git.md`) | 커밋당 1–3줄 | 1줄로 축약 (기록 자체는 유지) |
| 보고 (guidelines §5) | 변경 + 검증 5줄 이내 | 3줄 이내: 바꾼 것 + 확인 방법 |

## 그대로 유지 (비협상)

빠르게 간다는 것이 대충 간다는 뜻은 아니다. 아래는 애자일 모드에서도 그대로:

- **Simplicity·Surgical** (guidelines §2·§3) — 애자일의 핵심이 곧 이 두 원칙이다. 최소 코드, 요청 범위만.
- **Security** (`security.md`) — 시크릿·입력 검증 완화 없음.
- **커밋 컨벤션** (`git.md`) — 영/한 병기 메시지, specific `git add`.
- **빌드를 깨뜨린 채 done 금지** — 타입 에러·린트 에러가 남아 있으면 완료가 아니다 (warning 수준은 통과 허용).

## 이탈 조건

작업 중 범위가 커지는 순간 — 데이터 모델을 건드리게 되거나, 보안 표면에 닿거나, 수정이 세 번째 모듈로 번지면 — 멈추고 보고한다: "애자일 범위를 벗어났습니다. 여기부터는 일반 모드(테스트 포함)로 전환합니다." 조용히 애자일 모드로 밀어붙이지 않는다.

## 종료

애자일 모드는 사용자가 해제하거나("일반 모드로"), 이탈 조건이 발동하거나, 세션이 끝날 때까지 유지된다. 애자일 모드로 커밋한 작업이 나중에 중요해지면 테스트 보강이 필요할 수 있다 — 마지막 보고에 그 사실을 한 줄 남긴다 (예: "애자일 모드 구현 — 테스트 없음, 안정화 시 보강 권장").
